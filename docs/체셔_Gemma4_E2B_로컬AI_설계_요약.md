# 체셔 Gemma 4 E2B 로컬 AI 설계 요약

## 한 줄 결론

체셔는 사용자의 컴퓨터에서 실행되는 **Gemma 4 E2B**로 짧은 대사를 만들고, 퀴즈 정답·퍼즐 진행·감정 애니메이션 같은 게임의 중요한 판단은 기존 게임 로직이 맡는다.

그래서 EC2나 외부 AI API 키 없이도 체셔를 사용할 수 있고, 작은 모델을 써도 게임 진행이 틀어질 위험을 낮출 수 있다.

## 바뀌는 전체 구조

```text
현재
Unity 게임 → 인터넷 → EC2 FastAPI → Groq / Gemini API

변경 후
Unity 게임 → 사용자 PC의 FastAPI → 사용자 PC의 Gemma 4 E2B
```

변경 후에도 Unity는 지금처럼 `/chat/stream` 주소로 요청한다. 달라지는 것은 FastAPI가 외부 API 대신 같은 컴퓨터에서 실행 중인 Gemma 4 E2B에 요청한다는 점이다.

## 체셔 AI가 맡는 일

체셔는 '게임을 판단하는 AI'가 아니라, 정해진 정보를 체셔 말투로 바꾸는 **대사 생성기**로 사용한다.

| 담당 | 예시 |
|---|---|
| 체셔 AI | "흥, 침대 옆 서랍쯤은 네가 먼저 살펴볼 줄 알았는데." |
| 게임 로직 | 플레이어가 서랍을 조사했는지 판단 |
| 게임 로직 | 퀴즈 정답/오답 판정 |
| 게임 로직 | 다음 힌트 장소 결정 |
| 게임 로직 | 체셔 표정·애니메이션 변경 |

이렇게 하면 AI가 표현을 조금 반복하거나 어색하게 말할 수는 있어도, 퀘스트가 꼬이거나 퀴즈 판정이 틀어지지는 않는다.

## 대사 생성 규칙

Gemma 4 E2B에는 아래처럼 제한된 요청만 보낸다.

- 한국어로 1~2문장만 출력
- 체셔 특유의 장난스럽고 약간 오만한 말투 유지
- 게임이 전달한 사실만 사용
- 새로운 퍼즐 정답·장소·인물을 만들어내지 않음
- 생각 과정, JSON, 함수 호출, 시스템 메시지를 출력하지 않음
- 대사 최대 길이는 약 120토큰으로 제한

예를 들어 게임이 '침실 서랍을 조사하면 단서를 찾는다'고 결정한 뒤, AI에는 그 사실을 체셔 말투로 바꾸라는 요청만 준다.

## SSE 스트리밍은 유지한다

현재처럼 체셔의 말이 한 번에 뜨지 않고 생성되는 대로 표시할 수 있다.

```text
Gemma 4 E2B가 글자 생성
→ FastAPI가 SSE 이벤트로 변환
→ Unity가 받은 대사를 화면에 조금씩 표시
```

따라서 UI를 전부 다시 만들 필요는 없다. 단, Unity의 SSE 수신부는 네트워크 데이터가 중간에 끊겨 들어와도 대사가 누락되지 않도록 보완한다.

## 사용자의 컴퓨터에 설치되는 과정

1. 사용자가 게임을 처음 실행한다.
2. 게임이 로컬 AI 실행 환경과 모델 설치 여부를 확인한다.
3. 모델이 없다면 다운로드 용량과 오프라인 사용 가능 여부를 안내한다.
4. 사용자가 동의하면 Gemma 4 E2B 모델을 다운로드한다.
5. 로컬 AI 서버가 준비되면 게임이 체셔 채팅을 활성화한다.
6. 이후에는 인터넷이 없어도 체셔 대사를 생성할 수 있다.

모델 파일은 한 번 받은 뒤 PC에 남아 있으므로, 다음 실행부터 다시 내려받지 않는다.

## PC 권장 사양

체셔가 짧은 텍스트 대사만 만들고 모바일 최적화 LiteRT-LM 모델을 사용한다는 기준이다.

| 항목 | 최소 사용 기준 | 권장 |
|---|---|---|
| 운영체제 | Windows 10/11 64비트 | Windows 10/11 64비트 |
| RAM | 8GB (여유가 적음) | 16GB 이상 |
| CPU | 최근 4코어 CPU | 최근 6코어 CPU |
| 별도 그래픽카드 | 필요 없음 | 있으면 응답 속도 개선 |
| VRAM | 필수 아님 | 별도 GPU 사용 시 4GB 이상 권장 |
| 저장 공간 | 10GB 이상 여유 | 15GB 이상 여유 |

중요: 이 방식은 데스크톱에서도 모바일 최적화 모델을 사용하므로 8GB VRAM 그래픽카드를 필수 조건으로 잡지 않는다.

## 오류가 났을 때

| 상황 | 게임의 대응 |
|---|---|
| 모델 다운로드 실패 | 재시도 버튼 제공, 체셔 AI 기능은 잠시 비활성화 |
| 인터넷 없음 | 이미 설치된 모델이 있으면 정상 실행, 없으면 안내 표시 |
| PC 성능 부족 | AI를 끄고 미리 준비한 고정 체셔 대사 사용 |
| AI 응답이 이상함 | 금지 표현/길이 검사 후 미리 준비한 대사로 교체 |
| AI 실행 환경이 꺼짐 | 자동 재시작을 시도하고 실패 시 AI 기능만 비활성화 |

## 구현 순서

1. 체셔 대화에서 AI 도구 호출을 끄고, 대사 생성만 하도록 경계를 만든다.
2. Gemma 4 E2B 로컬 실행용 provider를 FastAPI에 추가한다.
3. Unity와 FastAPI 사이의 SSE 스트리밍을 안정화한다.
4. 최초 실행 시 모델을 내려받고 실행하는 설치 과정을 만든다.
5. 체셔 대사 예시 약 50개로 말투·사실성·반복 여부를 평가한다.
6. PC에서 충분히 검증한 뒤 Android/iOS용 온디바이스 모듈을 별도 구현한다.

## 이번 단계의 범위

첫 구현은 **Windows 데스크톱 버전**만 대상으로 한다. 모바일 버전은 같은 Gemma 4 E2B 모델과 대사 규칙을 공유하되, FastAPI와 SSE 대신 모바일용 네이티브 추론 모듈을 사용하므로 별도 작업으로 진행한다.
