# Cursor Agent 연결 안정성 설계

날짜: 2026-09-28  
상태: 설계 검토 대기  
범위: Codex가 저장소 래퍼를 통해 Cursor Agent CLI를 호출하는 경로

## 목표

Codex 작업에서 Cursor Composer 구현과 Cursor Auto 리뷰를 반복 가능하게 호출하고, 실제로 어떤 CLI·모델 경로·작업공간이 사용됐는지 증명한다. 사용자가 이미 로그인한 Cursor 계정 경로를 우선 사용하며, 별도 API 키 과금 경로로 몰래 전환하지 않는다.

## 확인된 현재 상태

- `scripts/run-cursor-subagent.ps1`은 Cursor CLI의 단일 진입점이며 Composer 구현과 Auto 읽기 전용 리뷰 인자를 구성한다.
- 사용자가 자신의 PowerShell에서 `agent status`를 실행했을 때 로그인 계정이 표시됐다.
- 같은 저장소 래퍼의 `-AuthStatus` 결과는 `Not logged in`이었고, Composer 호출은 `Authentication required`로 종료됐다.
- 이후 시작한 래퍼 로그인 흐름은 사용자가 중단했다. 따라서 이 세션에서 인증이나 Cursor 작업이 성공했다고 간주하지 않는다.
- 공식 Cursor CLI 문서는 `login`·`status`, 비대화형 `-p`, 모델 지정 및 출력 형식을 안내한다. 실제 설치된 CLI의 도움말과 버전이 공식 문서와 다르면 로컬 CLI 계약을 기록하고 문서 내용을 그대로 가정하지 않는다.

## 권장 설계

### 1. 단일 실행 환경을 인증 기준점으로 사용

저장소 래퍼가 실행하는 동일한 PowerShell 프로세스에서 CLI 경로, 버전, 현재 Windows 사용자, `USERPROFILE`, `HOME`, 그리고 `agent status`를 점검한다. 진단은 자격 증명 값 대신 상태 코드만 기록한다. `agent`가 여러 경로에서 발견되면 선택된 절대 경로를 표시하고, 호출 전후 경로가 달라지면 실행을 중단한다.

사용자 터미널과 래퍼 결과가 다르면 둘의 CLI 경로·버전·프로필 경로를 비교한다. 래퍼 기준 프로필에 로그인이 없는 경우 Cursor CLI의 공식 대화형 로그인 명령을 사용자가 한 번 완료하게 한다. 이메일·비밀번호·토큰을 문서, 저장소, 로그, 명령행 인자에 기록하지 않는다.

### 2. 인증과 작업 호출 사이에 읽기 전용 연결 검사

`-AuthStatus`를 기계 판독 가능한 결과로 확장하고, `-Probe`를 추가한다. Probe는 선택된 작업공간을 지정해 읽기 전용 질문 한 건을 실행하고, 시작 이벤트·최종 응답·프로세스 종료 코드를 확인한다. 인증 확인과 Probe가 통과하지 않으면 Composer나 리뷰 작업은 호출하지 않는다.

Probe는 사용자 파일을 생성하거나 수정하지 않는다. 응답이 단순히 CLI 실행 문자열을 출력한 것만으로 성공 처리하지 않고, CLI가 정상 종료하고 비어 있지 않은 최종 응답을 반환했는지 확인한다.

### 3. 각 호출을 추적 가능한 단일 작업으로 기록

각 실행에 로컬 `runId`를 부여하고 다음의 비밀이 아닌 메타데이터를 기록한다.

- 시작·종료 UTC 시각, 총 소요시간, 프로세스 종료 코드
- CLI 절대 경로와 버전, 실행한 작업공간, 인증 사전 점검 결과
- 요청된 작업 종류와 모델 별칭, CLI가 실제 모델을 보고한 경우 그 값
- 마지막 응답, 로그 파일 위치, timeout·인증·실행 실패 분류

원문 자격 증명과 `CURSOR_API_KEY` 값은 읽거나 기록하지 않는다. 환경에 `CURSOR_API_KEY`가 설정돼 있으면 값은 노출하지 않고 감지 사실만 표시하며, 기본 계정 로그인 경로와 충돌할 때는 명시적인 선택 없이 API 키 경로를 사용하지 않는다. 프롬프트 원문은 기본 로그에 저장하지 않는다.

Composer와 Auto 호출은 기존 저장소 계약을 유지한다. Composer는 `composer-2.5`로 쓰기 작업을 수행하고, Auto 리뷰는 `auto`와 읽기 전용 ask 모드를 사용한다. 요청 모델과 실제 보고된 모델은 분리해 기록하며 실제 모델이 확인되지 않으면 `unknown`으로 남긴다.

### 4. 종료·취소·재시도 상태를 명확히 처리

기본 작업 제한 시간은 저장소가 요구하는 단일 blocking 호출의 20분으로 한다. 완료·실패·인증 실패·timeout·사용자 취소를 서로 다른 결과로 반환한다. timeout이나 사용자 취소 뒤에도 Cursor 프로세스가 남아 변경을 계속하지 않도록 프로세스 트리를 정리하고, 새 실행은 이전 실행 종료를 확인한 뒤 시작한다. 자동 재시도로 동일 작업이 중복 실행되지 않게 하며 재시도는 별도 `runId`를 가진 명시적 새 호출로 처리한다.

로그가 조용하다는 이유만으로 실패나 완료로 추정하지 않는다. 기존 Cursor 래퍼 지침대로 blocking 실행을 기다리고, 실행 중 같은 체크아웃을 수정하지 않는다.

## 데이터 흐름

```text
Codex
  -> 저장소 Cursor 래퍼
      -> 실행 파일 / 버전 / 프로필 진단
      -> 같은 프로세스 환경에서 CLI status
      -> 인증 성공 시 읽기 전용 probe
      -> 검증 성공 시 Composer 구현 또는 Auto 리뷰 한 건
      -> 구조화 결과 + 비밀 없는 run 메타데이터
```

인증 또는 Probe 단계가 실패하면 종료하며, Cursor 호출 성공·작업 수행을 주장하지 않는다.

## 수용 기준

1. 래퍼의 인증 상태 결과가 같은 PowerShell에서 실행한 Cursor CLI 결과와 일치한다.
2. 로그인되지 않은 래퍼 환경은 구현·리뷰 호출 전에 명확한 인증 실패를 반환한다.
3. Probe가 선택한 작업공간과 최종 응답을 보여주며, 파일 변경이 없다.
4. Composer와 Auto 실행 결과에서 호출 경로, 요청 작업/모델, 실제 확인된 모델, 종료 코드와 최종 응답을 구분해 확인할 수 있다.
5. API 키가 설정되어 있어도 값이 노출되지 않고, 기본 동작이 API 키 과금 경로로 조용히 바뀌지 않는다.
6. timeout 및 취소 시 프로세스가 남지 않으며, 중복 호출이 자동으로 발생하지 않는다.
7. 연결 검증이 통과한 후 기존 QA 오토런 구현을 Cursor Composer로 재개하고, 별도 Cursor Auto 리뷰를 수행한다.

## 범위와 제외

예상 변경 파일은 `scripts/run-cursor-subagent.ps1`과 `docs/development/cursor-agent-access.md` 및 래퍼의 관련 테스트로 제한한다. 연결이 안정화되기 전에 QA 구현 변경을 다시 호출하지 않는다. Cursor 계정 비밀번호·토큰 저장, API 사용량 기반 호출, Cursor 데스크톱 UI 자동화는 제외한다.

## 검증 계획

1. 래퍼의 dry-run에서 실행 경로·작업공간·요청 모드를 확인한다.
2. `-AuthStatus` 결과를 현재 터미널의 `agent status`와 비교한다.
3. 로그아웃/잘못된 프로필 조건에서 Probe와 작업 호출이 차단되는지 검사한다.
4. 로그인된 동일 프로필에서 읽기 전용 Probe를 실행해 응답 및 종료 증거를 확인한다.
5. 이후 별도 작업으로 Composer 호출과 Auto 리뷰 호출을 각각 수행해 의도한 권한과 모델 경로를 검증한다.
6. 실패·timeout·취소 경로에서 종료 상태와 자식 프로세스 정리를 확인한다.

이 문서는 설계 승인 전 초안이다. 구현 전에 사용자 검토를 받는다.
