# SettingScene 레이아웃·컨트롤·해상도 명세 v2

작성일: 2026-09-10. 상태: 수정안, Unity 적용·플레이 검증 전.
요청: 첨부된 SettingScene의 레이아웃과 버튼 크기를 다시 맞추고 해상도별 수치를 정의한다.
시각 방향: 기존 01 목재 패널의 어두운 갈색·금색·각진 컨트롤을 유지한다.
본 문서는 기존 `docs/ui-mockups/settings-2026-09-10/01-ui-spec.html`의 레이아웃·크기·반응형 제안값을 대체한다. 색상, 설정 기능, 언어·체셔 체험 계약은 유지한다.

## 1. 적용 대상과 확인된 문제

사용자가 지정한 대상은 SettingScene이다. `unity-cli status`가 보고한 실행 프로젝트는 `C:/Users/user/orca/workspaces/newCapstone/develop/disputatio`, Editor는 6000.0.36f1, connector는 0.3.21이다. 문서 작성 checkout은 `C:/Users/user/Documents/GitHub/newCapstone`이며 두 경로는 다르다.

첨부 이미지에서 관찰한 문제:

- 브랜드와 상단 보조 문구가 패널 위로 벗어나거나 겹친다.
- `1920 x 1080`이 드롭다운 한 줄에 들어가지 않고 컨트롤 높이를 넘는다.
- 펼친 목록은 본체와 색상·폰트 크기가 다르고 마지막 항목이 잘린다.
- 본문 라벨·탭 텍스트는 작은데 일부 드롭다운 텍스트만 지나치게 크다.
- 전체화면 조작부가 식별되지 않고 언어·글자 크기 조작부는 오른쪽에서 잘린다.
- 패널·본문을 과도하게 가로로 늘려 라벨과 컨트롤 사이가 벌어진다.

이미지의 파일 크기는 실제 게임 렌더 해상도를 증명하지 않는다. 드롭다운에 표시된 해상도도 현재 Game View 크기를 증명하지 않는다. 아래 표는 새 설계값이며 첨부 이미지에서 역산한 실측값이 아니다.

실행 프로젝트의 읽기 전용 조사에서 확인한 구현 조건:

- `SettingsWoodPanelSpec.cs`는 HTML 제안값과 같은 UI font 14, control width 180, tab height 44를 Unity 상수로 사용한다.
- `SettingsShellFactory.Build`는 전달된 panelRoot에 root를 stretch한다. 부모 크기·스케일을 확인하지 않으면 최종 경계를 보장할 수 없다.
- `CreateSettingsRow`의 컨트롤 높이는 32 기준이다. `StyleWoodDropdown`은 caption/item 폰트 크기·줄바꿈·내부 여백 전체를 하나의 계약으로 지정하지 않는다.
- `SettingDisplayControlsFactory`는 기존 컨트롤을 새 행으로 옮긴다. 기존 RectTransform·폰트·Template 상태가 남는지 조사해야 한다.

이 조건은 수정 지점을 식별하는 근거다. 실제 clipping의 최종 원인은 실행 중 부모 RectTransform과 생성된 컨트롤을 측정해 확인한다.

## 2. 좌표와 스케일의 단일 기준

모든 아래 치수는 1920×1080 기준의 Unity UI 논리 단위 U다. HTML 미리보기에서는 1U를 기준 캔버스의 1px로 대응시킨 뒤 같은 배율로 전체를 축소한다. CSS px 값을 별도 해석해 Unity에 복사하지 않는다.

- CanvasScaler: Scale With Screen Size, Reference Resolution 1920×1080, Screen Match Mode **Expand**.
- 전용 설정 Canvas 또는 동등한 단일 스케일 경로를 사용한다. 부모·자식 Canvas에서 이중 보정하지 않는다.
- 배율 `s = min(W / 1920, H / 1080)`.
- 설정 프레임: **1680×936U**, 화면 중앙. 가로로 stretch하지 않는다.
- 실제 프레임 크기: `(1680s, 936s)`px.
- 실제 프레임 좌상단: `((W−1680s)/2, (H−936s)/2)`px.
- W/H는 설정 UI가 사용하는 실제 렌더 영역이다. Screen Space Camera라면 해당 camera pixelRect를 확인한다. OS 창 테두리는 포함하지 않는다.
- 일반 PC 전체 뷰포트를 기준으로 하며 safe area가 존재하면 가용 사각형에 같은 공식을 적용한다.
- 16:10·21:9·5:4는 프레임 비율을 유지하고 배경 영역만 더 보여준다. 넓은 화면에서 라벨과 컨트롤 간격을 늘리지 않는다.
- 최소 검증 대상은 1280×720이다. 그보다 작은 뷰포트는 지원 검증 밖이며 자동으로 글자를 더 작게 만드는 완료 기준을 만들지 않는다.

기존 HTML의 850px 이하 모바일 한 열 전환은 이 PC용 Unity 명세에 적용하지 않는다. 새 런타임 크기 보정 MonoBehaviour나 Update 루프를 추가하지 않고 CanvasScaler·RectTransform·기존 레이아웃 소유자에서 해결한다.

## 3. 프레임 내부 배치

좌표는 프레임 좌상단 기준 `(x, y, width, height)`이며 y는 아래로 증가한다. Unity top-left pivot에서 anchoredPosition은 `(x, −y)`로 변환한다.

| 영역 | 논리 사각형 U | 규칙 |
|---|---|---|
| 프레임 | 0, 0, 1680, 936 | 실제 목재 sprite 장식은 별도 배경. 콘텐츠 경계를 밀지 않음 |
| 내부 안전 영역 | 32, 32, 1616, 872 | 사방 32U |
| 사이드바 | 32, 32, 256, 872 | 폭 고정 |
| 본문 열 | 320, 32, 1328, 872 | 사이드바와 32U 간격 |
| 헤더 | 320, 32, 1328, 104 | 제목·설명·구분선 포함 |
| 본문 스크롤 영역 | 320, 160, 1328, 632 | 헤더 다음 24U. 세 탭에서 동일 영역 |
| 푸터 | 320, 816, 1328, 88 | 본문 다음 24U. 탭 변경·본문 길이와 무관하게 고정 |

목재 sprite의 border 수치는 9-slice 설정이다. 콘텐츠 padding 32U와 혼합하거나 `WoodInnerInset`을 별도로 누적하지 않는다. sprite의 장식이 안전 영역을 침범하면 배경 sprite 표시를 조정하고 콘텐츠 좌표는 유지한다.

### 헤더·브랜드·탭

- 브랜드는 sidebar 내부 x=16, y=16, w=224, h=48U. 보조 문구는 x=16, y=72, w=224, h=24U. 음수 높이/부모 밖 offset 금지.
- 탭 시작 y=136U, 버튼 256×80U, 간격 16U. 세 탭의 위치는 선택 시 변하지 않는다.
- 탭 안쪽 좌우 16U. 선택 마커 8U, 마커 자리 16U, 번호 자리 32U, 번호 뒤 8U를 항상 예약한다.
- 탭 텍스트는 최대 2줄, 줄높이 1.2. 긴 영어 탭을 잘라내거나 폰트 축소로 해결하지 않는다.
- 본문 제목 x=0, y=8, h=48U. 보조 설명 y=64, h=28U. 제목과 설명은 독립 RectTransform으로 배치한다.
- 기본 설정 탭 제목은 **기본 설정**으로 통일한다. 음량과 화면 항목이 함께 있는데 전체 제목을 사운드로 표시하지 않는다.

## 5. 텍스트와 펼친 드롭다운

| 용도 | 글자 크기 U | 1280×720에서 예상 px |
|---|---|---|

| 브랜드 | 36 | 24 |
| 행 라벨·버튼·탭·선택값·목록 항목 | 24 | 16 |

| 체셔 답변 100/120/140% | 27 / 32.4 / 37.8 | 18 / 21.6 / 25.2 |

일반 UI 크기를 답변 글자 크기 설정에 연결하지 않는다. KO/EN/JA에 읽을 수 있는 TMP 폰트·폴백을 유지하고, 해상도 숫자에는 장식용 브랜드 폰트를 사용하지 않는다.

드롭다운 계약:

- captionText와 itemText 모두 fontSize=24U, 한 줄, 가운데 높이 정렬. auto-size로 가독성을 낮추지 않는다.
- 해상도 표기는 `1920 × 1080` 한 줄. 값이 들어갈 너비 248U 확보. 옵션 끝자리 누락·줄바꿈·말줄임 금지.
- Template 폭 320U, 항목 높이 64U, 최대 5개 표시. 상하 padding 각 8U → 최대 높이 336U.
- 본체와 목록 배경 #151310, 글자 #E8D6AC, 테두리 #65503A, 선택 배경 #49351E, 강조 #D0AB5D. 흰색 기본 Template/Item 배경이 남지 않아야 한다.
- 목록 스크롤바 폭 12U, thumb 최소 높이 32U. 화살표·checkbox에 사각형 placeholder 대신 기존 적합 sprite 또는 명시된 단순 도형 사용.
- 목록은 가장 가까운 안전 경계 안에 배치한다. 아래에 공간이 없으면 위로 연다. Canvas 밖 또는 본문 Mask 아래에서 잘리지 않도록 실제 popup canvas/sorting을 확인한다.
- 5개 초과 옵션은 목록 내부 스크롤. 클릭 차단 영역과 Escape는 첫 입력에 목록만 닫고 설정창은 유지한다.

지원 레이아웃 해상도와 실제 선택 가능한 디스플레이 모드는 다르다. 아래 QA 표를 해상도 dropdown 옵션에 무조건 추가하지 않는다. 장치가 제공하는 유효한 모드와 기존 적용·저장 로직을 보존한다.

## 8. 수용 기준과 플레이 검증

- L01: 표의 모든 해상도에서 프레임 사각형과 중심이 기대값 ±1px 이내이며 콘텐츠가 프레임 안에 있다.
- L02: 기본 설정/체셔 AI/언어 탭 전환 전후 프레임·헤더·푸터·탭 위치가 변하지 않는다. 긴 본문만 내부 스크롤한다.
- L03: `1920 × 1080`, `3840 × 2160`, English, 日本語가 caption과 펼친 목록에서 한 줄로 보이고 실제 텍스트 bounds가 컨트롤을 넘지 않는다.
- L04: dropdown 본체·목록·선택·포커스 색상이 일치하고 흰 기본 배경·흰 사각 화살표가 없다.
- L05: 전체화면 checkbox와 상태 텍스트가 보이고 클릭·키보드로 변경된다. slider thumb는 찌그러지지 않고 drag가 된다.
- L06: 저장→씬 재진입 및 PlayMode 재시작 후 같은 레이아웃과 설정값을 유지한다. 일회성 보정 명령을 다시 실행하지 않는다.
- L07: KO/EN/JA, 답변 100/120/140%, 긴 체셔 답변에서도 푸터와 질문 조작부에 접근할 수 있다. AI 동작 계약은 기존 명세 유지.
- L08: 변경된 실제 해상도와 Game View 픽셀 크기를 기록한다. dropdown 표시값만 보고 해상도 검증 완료로 판단하지 않는다.

우선 플레이 세트: 1280×720, 1366×768, 1920×1080, 3440×1440에서 기본·언어 탭과 dropdown 펼침 상태를 캡처한다. 나머지 표 해상도도 경계와 입력을 확인한다. 설정 씬을 먼저 검증하고 공유 factory 변경의 회귀로 게임 중 패널을 확인한다. 캡처·테스트·실제 수정은 수행 전까지 미검증이다.

## 9. 문서 우선순위와 인계

이 문서 v2가 크기·레이아웃 기준이며 기존 HTML 치수와 충돌하면 v2를 따른다. 기존 HTML은 시각 방향 참고로 보존한다. 현재 UI가 다른 checkout에서 생성된 사실, 해당 코드 revision·diff, Editor 소유자, 이번 문서 경로를 작업 패킷에 남긴다. 실제 게임 수정 완료와 명세 작성 완료를 구분해서 보고한다.
