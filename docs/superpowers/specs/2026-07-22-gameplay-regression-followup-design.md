# 게임플레이 회귀 버그 후속 검증 및 보완 설계

## 목적

`develop`에 병합된 `a3bad1ff`의 회귀 수정은 유지하면서, Kitchen, Hall, TutorRoom, MaidRoom 제보를 재현 가능한 테스트로 다시 확인하고 아직 남아 있는 동작만 최소 범위로 보완한다. 완료 조건은 코드가 존재하는 것이 아니라 Unity에서 새 게임 2회차를 포함한 실제 플레이 흐름이 통과하는 것이다.

## 현재 상태와 원인 판정

| 영역 | 확인된 상태 | 원인 또는 남은 불확실성 |
|---|---|---|
| Kitchen 수도꼭지·물통·열쇠 | `KitchenPuzzleState`가 `GetBottle`, `BottleClicked`, `FaucetClicked`, `BottleDragged`를 소유하고 Fungus 변수에 미러한다. 최근 패치에서 완료 대사의 잘못된 `FaucetClicked` 조건을 `HaveMaidKey`로 변경했다. | 과거에는 여러 클릭 진입점과 Fungus 분기가 같은 bool을 서로 다른 시점에 변경해 연출과 입력 잠금이 어긋났다. 현재 코드의 순차 연출과 열쇠 클릭 가능 시점은 수동 검증이 남아 있다. |
| Kitchen 체셔 재대화 | `KitchenParretInteractionGate`가 `ComeParret && !ParretClicked`일 때만 `parret` 블록을 실행한다. | 두 번째 무반응은 현재 코드상 우연이 아니라 명시적인 1회 제한이다. 요구사항은 최초 Fungus 대사만 1회로 제한하고 이후 일반 AI 대화는 반복 허용하는 것으로 확정한다. |
| Hall 새 게임·지도·인벤토리 | 최근 패치가 PlayerPrefs 정리 외에 Fungus reset, 인벤토리 드래그 상태, `DontDestroyOnLoad` 게임플레이 루트 정리를 추가했다. | 과거에는 저장 데이터와 런타임 전역 상태의 초기화 경계가 달랐기 때문에 지도 진행은 남고 UI 아이템만 사라졌다. 2회차 시작의 통합 검증이 필요하다. |
| Hall 퀘스트 | `TutorialQuestProgressAdapter`는 Kitchen 씬 입장을 `go_kitchen`, `ElectricOn`을 `raise_breaker`로 별도 매핑하며 최종 퀘스트 다음 ID는 `null`이다. HUD에는 최종 dismiss 패치가 들어갔다. | 과거에는 씬 진입 이벤트가 누락되고 최종 퀘스트에 다음 ID가 없을 때 HUD 종료 분기가 없었다. 씬 진입 catch-up과 최종 HUD 비활성화를 함께 검증해야 한다. |
| TutorRoom 체셔 | 채팅 전송은 timeout/재시도/finally 정리 패치가 들어갔다. 문제 진행은 `TutorQuizStateTracker`와 서버 `/tutor/grade`에 의존하며 목표 정답 수는 5이다. | “생각 중” 정지는 HTTP 완료·오류 경로에서 요청 플래그와 입력 잠금이 풀리지 않던 문제였다. 현재 구조는 CSV에서 세션별 5문제를 직접 무작위 선정한다는 요구를 명시적으로 보장하지 않는다. |
| MaidRoom food 이펙트 | 씬 YAML과 `MaidRoomSceneFlowTests`는 `food` 블록의 pickup 및 `FoodItemEffect` 비활성화를 고정한다. | 이펙트 크기를 `0.01`로 줄이는 방법은 보이지 않게 할 뿐 수명 주기 오류를 해결하지 않는다. Flowchart 중단 시 SetActive 명령까지 도달하지 못하는 경로가 남는다. |

## 선택한 접근

기존 수정 유지와 미해결 항목 보완 방식을 사용한다. 이미 도입된 C# 상태 소유자와 작은 정책 클래스를 유지하고, 씬/Fungus는 표현과 대사 순서를 담당하게 한다. 전체 Kitchen 상태 머신 재작성이나 씬 명령만의 재배선은 이번 후속 범위에 포함하지 않는다.

## 설계

### 1. Kitchen 상호작용

`KitchenPuzzleState`를 싱크 퍼즐의 단일 상태 권한으로 유지한다. 월드 클릭은 `KitchenInteractionController`를 통하고, 블록 실행 전 현재 상태를 Fungus에 미러하며, 블록이 정상 종료된 뒤에만 상태를 전진시킨다. 중복 클릭은 현재 단계와 맞지 않으면 무시하되 입력 잠금은 남기지 않는다.

물 채우기 완료 흐름은 `Faucet` 또는 병 드롭 진입점에서 한 번만 시작하여 암전, 물소리, 물 표시 정리, 열쇠 표시, 열쇠 collider/interactable 활성화 순서로 끝난다. 임의 시간 후 입력을 푸는 대신 연출 코루틴 또는 Fungus 블록 완료를 열쇠 활성화 조건으로 사용한다. 실패나 중단 경로에서는 입력 잠금을 `finally` 성격의 정리 지점에서 해제한다.

체셔는 최초 음식 전달 대사와 이후 대화의 소유권을 분리한다. `ParretClicked`는 최초 이벤트 재실행만 막고, 이후 클릭은 일반 `KitchenChatbot` 대화 진입점으로 전달한다. AI 요청이 진행 중인 경우만 중복 요청을 거절하며, 요청 종료 후에는 다시 클릭할 수 있어야 한다.

### 2. 새 게임 데이터 경계

새 게임은 하나의 reset 진입점에서 다음을 함께 초기화한다.

- 진행 PlayerPrefs와 방·퍼즐·퀘스트 플래그
- Fungus SaveManager 및 전역 게임플레이 변수
- 런타임 인벤토리 목록과 drag 상태
- 씬 간 생존하는 게임플레이 관리자 및 열려 있는 인벤토리 UI

BGM, SFX, 전체 화면, 해상도 설정은 보존한다. 메인 화면 복귀는 새 게임 시작과 구분하되, 다음 실행에 이전 런타임 루트가 섞이지 않도록 게임플레이 루트를 제거한다. 씬 로드 직후 UI는 자체 복제본이 아니라 현재 전역 인벤토리 데이터를 읽어 새로 그린다.

### 3. 퀘스트 전이

Kitchen 씬 로드 완료 시 현재 퀘스트가 `light_the_manor`이면 `go_kitchen` 단계를 완료한다. `ElectricOn`은 별도 단계만 완료하므로 다용도실의 불 켜기가 주방 입장을 대신하지 않는다. 이미 월드 상태가 앞서간 저장이나 씬 재진입은 `ResolveCatchUpStepIds`로 순서대로 보정한다.

퀘스트 완료 후 다음 ID가 있으면 crossfade하고, 없으면 완료 표시 후 HUD alpha를 0으로 만들고 루트를 비활성화한다. 완료 상태 자체는 새 게임 reset 전까지 유지한다.

### 4. TutorRoom 문제 세션

퀴즈 CSV를 읽는 문제 저장소와 세션 선택기를 분리한다. 저장소는 유효한 `question_id`, 질문, 정답/채점 참조를 파싱하고 중복 ID와 필수 열 누락을 오류로 보고한다. 세션 선택기는 시작 시 seed 가능한 셔플을 한 번 수행하여 중복 없는 5개 ID를 고정한다. 같은 세션의 재질문이나 오답 처리에서는 새로 셔플하지 않는다.

클라이언트가 출제하는 `question_id`와 `/tutor/grade`가 채점하는 ID는 동일해야 한다. 유효 문제가 5개 미만이면 “생각 중” 상태에 머물지 않고 지역화된 오류를 표시하고 입력 잠금을 해제한다. HTTP timeout, 파싱 오류, GameObject 비활성화에서도 요청 진행 플래그와 입력 gate를 반드시 해제한다.

### 5. MaidRoom 이펙트 수명 주기

food 아이템 획득의 성공 여부를 C# pickup 완료 이벤트가 소유하도록 한다. 성공 시 pickup과 이펙트를 함께 비활성화한다. Flowchart 대사나 후속 명령이 실패하더라도 획득이 확정된 경우 이펙트 정리는 실행된다. 획득이 취소되면 둘 다 유지한다.

Hierarchy용 크기 조절 부모는 시각 크기 조정에만 사용할 수 있으며 정리 로직으로 간주하지 않는다. 씬 YAML 테스트는 참조가 사라지지 않았는지 확인하고, 동작 테스트는 성공·취소·Flowchart 중단 세 경로를 확인한다.

## 오류 처리와 관측성

- 모든 비동기 입력 잠금은 시작/종료 로그와 짝을 이루고 종료 경로에서 해제한다.
- 상태 전이는 이전 단계, 이벤트, 다음 단계를 한 줄 로그로 남긴다.
- CSV 오류는 파일/행/question ID를 포함한다.
- 씬의 직렬화 참조는 EditMode YAML 테스트로 잠근다.
- 실제 플레이 중 예상하지 못한 블록 중단은 아이템·입력 상태를 포함해 기록한다.

## 검증 기준

1. 깨끗한 시작에서 수도꼭지 선행 클릭, 물통 획득, 물 채우기, 암전·물소리, 열쇠 즉시 클릭이 순서대로 동작한다.
2. 각 단계에서 연속 클릭해도 블록이 중복 실행되지 않고 입력이 영구 잠기지 않는다.
3. 음식 전달 후 첫 대사는 한 번만 나오며 두 번째 클릭부터 일반 AI 대화가 가능하다.
4. 아이템과 퀘스트를 진행한 뒤 메인 화면으로 돌아와 새 게임을 시작하면 지도·인벤토리·퀘스트·Fungus 상태가 모두 초기화되고 환경 설정은 유지된다.
5. Kitchen 입장 즉시 해당 퀘스트 단계가 완료되고, 마지막 퀘스트 완료 후 HUD가 닫힌다.
6. TutorRoom은 CSV에서 중복 없는 5문제를 세션 동안 출제하고 timeout 또는 잘못된 CSV에서도 입력을 복구한다.
7. food 획득 성공 및 Flowchart 후속 오류에서도 이펙트가 사라지며, 취소 시에는 남는다.

## 범위 제외

- 전체 Fungus 시스템 제거 또는 모든 방의 상태 머신 재작성
- 기존 저장 파일의 장기 마이그레이션 체계 신설
- TutorRoom 문제 내용 자체의 편집
- 이 제보와 무관한 UI·아트 리팩터링
